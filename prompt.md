# Промпт для реализации страницы "Питание" (Nutrition)

## Общее описание
Необходимо создать страницу **Питание** (`layout/app/pages/Nutrition.tsx`) с интеграцией данных между страницами **Главная**, **Уведомления**, **Холодильник** и самой страницей Питание. Все данные о приёмах пищи, калориях и БЖУ должны быть синхронизированы через общее состояние (React Context, Zustand, Redux или аналогичное).

## Требования к синхронизации данных

### 1. Секция "Калории"
- Секция калорий на странице **Питание** должна использовать те же данные, что и секция калорий на странице **Главная** (`layout/app/pages/Home.tsx`).
- При обновлении калорий на любой из страниц данные должны автоматически обновляться везде.

### 2. БЖУ и графики
- Белки, жиры, углеводы (БЖУ) рассчитываются на основе данных из секции **"Приемы пищи"**.
- Те же данные БЖУ используются для построения графиков на странице **Питание**.
- Источник данных БЖУ — объект приёмов пищи, общий для страниц:
  - **Питание**
  - **Главная**
  - **Уведомления** (`layout/app/pages/Reminders.tsx`)

### 3. Единый объект "Приемы пищи"
- Все страницы должны ссылаться на один и тот же объект состояния приёмов пищи.
- Изменения в списке приёмов пищи на любой странице должны мгновенно отражаться на остальных.

## Функционал взаимодействия с холодильником

### 4. Добавление продуктов из холодильника в приём пищи
- На странице **Питание** пользователь может выбрать продукт из списка холодильника (данные берутся со страницы **Холодильник** `layout/app/pages/Fridge.tsx`).
- При добавлении продукта в приём пищи:
  - Количество продукта в холодильнике уменьшается на указанную величину.
  - Продукт добавляется в текущий приём пищи как элемент списка с указанием количества и питательной ценности (калории, БЖУ).

### 5. Удаление продукта из холодильника при нулевом остатке
- Если после вычитания количество продукта в холодильнике становится равным 0, продукт автоматически удаляется из списка холодильника.
- Состояние холодильника обновляется везде, где оно используется.

### 6. Очистка приёма пищи
- Должна быть кнопка/функция "Очистить приём пищи", которая удаляет все продукты из текущего приёма пищи.
- При очистке количество продуктов, ранее добавленных в приём пищи, должно возвращаться обратно в холодильник (или просто продукты удаляются из приёма, не влияя на холодильник — уточнить у пользователя; по умолчанию возвращать в холодильник).
- После очистки пользователь может сформировать новый рацион.

## Технические рекомендации

- **State Management**: Использовать общий стор (например, React Context с провайдером в `layout/app/App.tsx` или отдельный стор wie Zustand) для хранения:
  - Список приёмов пищи (массив объектов с продуктами и итоговыми БЖУ/калориями)
  - Состояние холодильника (список продуктов с количеством и пищевой ценностью)
  - Итоговые калории и БЖУ (можно вычислять из приёмов пищи)

- **Компоненты UI**: Переиспользовать существующие UI-компоненты из `layout/app/components/ui` (таблицы, карточки, кнопки, модальные окна и т.д.) для единообразного вида.

- **Графики**: Для визуализации БЖУ и калорий можно использовать библиотеку, уже присутствующую в проекте (например, реестр компонентов содержит `chart.tsx`).

- **Типизация**: Если проект использует TypeScript — добавить типы для объектов еды, приёмов пищи и состояния холодильника.

- **Асинхронность**: Если данные хранятся в локальном хранилище или на сервере — предусмотреть загрузку/сохранение состояния.

## Файлы, которые следует задействовать или модифицировать
- `layout/app/pages/Nutrition.tsx` — основная страница
- `layout/app/pages/Home.tsx` — синхронизация секции калорий

- Компоненты UI из `layout/app/components/ui` (по необходимости)

## Пример структуры состояния (псевдокод)
```ts
interface FoodItem {
  id: string;
  name: string;
  caloriesPer100g: number;
  proteinPer100g: number;
  fatPer100g: number;
  carbsPer100g: number;
}

interface FridgeItem extends FoodItem {
  quantity: number; // в граммах или штуках
}

interface MealItem {
  foodId: string;
  quantity: number; // количество выбранного продукта
}

interface Meal {
  id: string;
  name: string; // например, "Завтрак", "Обед"
  items: MealItem[];
  totals: {
    calories: number;
    protein: number;
    fat: number;
    carbs: number;
  };
}

interface AppState {
  meals: Meal[]; // общий список приёмов пищи
  fridge: FridgeItem[]; // contents of the fridge
  // методы: addToMeal, removeFromFridge, clearMeal, updateFridgeQuantity, etc.
}
```

## Критерии готовности
- [ ] Секция калорий на Питание синхронна с Главной.
- [ ] БЖУ и графики рассчитываются из текущих приёмов пищи.
- [ ] Приёмы пищи одинаковы на Питание, Главная и Уведомления.
- [ ] Добавление продукта из холодильника уменьшает его количество там и добавляет в приём пищи.
- [ ] При нулевом количестве продукт удаляется из холодильника.
- [ ] Есть возможность очистить текущий приём пищи от продуктов (с возвратом в холодильник или без — уточнить).
- [ ] Все изменения отражаются в реальном времени на всех связанных страницах.
- [ ] Код чистый, следует существующим стилям и conventions проекта.

> **Примечание**: Перед началом работы рекомендуется изучить текущую реализацию схожих функций в других страницах (например, как реализовано хранение данных в Reminders или Home) и повторить паттерны.
