# Промпт для реализации страницы "Профиль"

## Общее описание
Необходимо создать страницу **Профиль** (предположительно `layout/app/pages/Profile.tsx`) с отображением данных пользователя, возможностью редактирования профиля, выхода из аккаунта и просмотра статуса подписки. Данные пользователя должны синхронизироваться с другими страницами приложения (например, отображение имени в шапке) и получаться/обновляться через API бэкенда.

## Требования к функционалу

### 1. Отображение данных пользователя
- При загрузке страницы выполнить GET запрос к API эндпоинту (например, `/api/user/profile`) для получения данных текущего пользователя.
- Отобразить следующие поля:
  - Аватар (изображение или инициалы)
  - Полное имя
  - Email
  - Дата регистрации (опционально)
  - Другие поля, возвращаемые API (например, телефон, дата рождения — если требуется отображение)

### 2. Возможность редактирования профиля
- Кнопка **"Редактировать профиль"**, которая переводит пользователя в режим редактирования или открывает модальное окно/Drawer с формой.
- Форма редактирования должна содержать поля для изменения:
  - Имя
  - Email (если разрешено изменять)
  - Аватар (загрузка изображения с предпросмотром)
  - Другиеeditable поля из ответа API
- При отправке формы выполнить PATCH/PUT запрос к API (например, `/api/user/profile`) с обновленными данными.
- После успешного обновления:
  - Обновить локальное состояние/кеш
  - Синхронно обновить отображаемые данные на странице профиля и на других страницах, где используется информация о пользователе (например, шапка приложения)
  - Показать уведомление об успехе (используя существующую систему уведомлений, например, sonner/toast)
- Обработка ошибок валидации и сетевых ошибок с выводом соответствующих сообщений.

### 3. Выход из аккаунта
- Кнопка **"Выход"** или **"Выйти из аккаунта"** (возможно в выпадающем меню профиля).
- При подтверждении действия:
  - Выполнить POST запрос к API эндпоинту logout (например, `/api/auth/logout`) для очистки серверной сессии (если требуется).
  - Очистить локальное состояние/токены/кеш пользователя (например, удалить данные из контекста или хранилища).
  - Перенаправить пользователя на страницу входа (`/login`) или главную страницу в режиме гостя.

### 4. Блок статуса подписки
- Небольшая секция на странице профиля с информацией о текущей подписке пользователя.
- Получить данные о подписке через отдельный API запрос (например, `/api/user/subscription`) или как часть основного профиля.
- Отобразить:
  - Текущий план подписки (например, "Бесплатный", "Премиум", "Пробный")
  - Дата начала и окончания периода (если применимо)
  - Статус (активен, истекает через X дней, неактивен)
- Кнопка **"Купить Premium"** или **"Оформить подписку"**, которая при клике перенаправляет пользователя на страницу покупки премиум-подписки (предположительно `/subscription` или `/premium`).
- Если пользователь уже имеет премиум-подписку, кнопка может быть неактивной или отображать сообщение "У вас уже активна Premium подписка".

## Требования к синхронизации данных

### 5. Единое состояние пользователя
- Данные о пользователе (имя, email, аватар и т.д.) должны храниться в общем стейте (React Context, Zustand, Redux и т.п.) с провайдером на уровне приложения (например, в `layout/app/App.tsx`).
- При успешном входе, обновлении профиля или выходе из аккаунта обновлять этот глобальный стейт.
- Все компоненты, которым нужны данные пользователя (например, шапка приложения, меню, другие страницы) должны подписываться на изменения этого стейта и автоматически обновлять отображаемую информацию.

### 6. Кеширование и оптимизация
- При успешной загрузке профиля сохранять данные в кеш (например, в React Query/SWR или собственном кэше контекста) для уменьшения количества запросов при навигации.
- При обновлении профиля через форму оптимистично обновлять UI, ожидая подтверждения от сервера (опционально, но рекомендуется для лучшего UX).

## Технические рекомендации

- **API Integration**: Использовать существующий механизм запросов к API (например, axios-инстанс или fetch-хелпер из `layout/lib/api.ts` или подобного). Если такого нет — создать универсальный API-клиент с обработкой ошибок, заголовков авторизации (Bearer токен) и базового URL.
- **State Management**: 
  - Для простых данных (имя, аватар) можно использовать React Context с провайдером `AuthProvider` или `UserProvider`.
  - Для более сложной логики (кеширование, фоновые обновления) рассмотреть React Query или SWR.
- **Компоненты UI**: Переиспользовать существующие UI-компоненты из `layout/app/components/ui`:
  - Карточки (`card.tsx`) для блоков информации
  - Кнопки (`button.tsx`)
  - Поля ввода (`input.tsx`, `textarea.tsx`)
  - Загрузчики аватара (можно адаптировать из существующих компонентов загрузки файлов или использовать `input[type="file"]` с предпросмотром)
  - Модальные окна/Drawer (`dialog.tsx`, `drawer.tsx`) для формы редактирования
  - Индикаторы загрузки (`skeleton.tsx` или `spinner` если есть)
  - Уведомления (sonner/toast — уже используется в проекте, см. `sonner.tsx`)
- **Валидация форм**: Использовать библиотеку валидации (например, React Hook Form с Yup) или собственную логику, соблюдая существующие паттерны проекта.
- **Аватары**: При отсутствии изображения аватарки отображать инициалы пользователя (как в существующих компонентах, если они есть — например, в `avatar.tsx` из ui-папки).
- **Типизация**: Если проект на TypeScript — определить типы для ответов API профиля и подписки, а также для форм редактирования.
- **Обработка загрузки и ошибок**: Показывать скелетоны/спиннеры во время запросов, отображать сообщения об ошибках в удобном для пользователя виде.

## Файлы, которые следует задействовать или создать
- `layout/app/pages/Profile.tsx` — основная страница профиля
- `layout/app/components/profile/` (опционально) — переиспользуемые компоненты специфичные для профиля (например, `ProfileAvatar`, `ProfileStats`)
- `layout/app/context/UserContext.ts` (или аналогичное) — контекст для хранения данных пользователя и методов обновления/выхода
- `layout/lib/api.ts` — расширение существующего API-клиента методами для профиля (если такого файла нет — создать)
- `layout/app/hooks/useUser.ts` (опционально) — кастомный хук для доступа к данным пользователя и методов их изменения
- Компоненты UI из `layout/app/components/ui` (по необходимости)
- Если требуется страница покупки Premium — предположительно она уже существует или будет создана отдельно (`layout/app/pages/Subscription.tsx` или подобное)

## Критерии готовности
- [ ] При открытии страницы профиля отображаются актуальные данные пользователя (аватар, имя, email и т.д.) после загрузки через API.
- [ ] Есть возможность редактировать профиля с сохранением изменений через API и синхронным обновлением UI на всех страницах.
- [ ] Кнопка выхода из аккаунта очищает сеанс и перенаправляет на страницу входа.
- [ ] Блок статуса подписки показывает текущий план и имеет кнопку перехода на страницу покупки Premium.
- [ ] Данные пользователя (имя, аватар) синхронно обновляются в других частях приложения (например, в шапке) после изменения профиля.
- [ ] Обработаны состояния загрузки, ошибок и пустых данных (например, показаны скелетоны при запросе).
- [ ] Валидация полей формы редактирования работает корректно (например, email должен быть валидным).
- [ ] Код следует существующим стилям, использует переиспользуемые компоненты и паттерны проекта.
- [ ] При необходимости реализована оптимистическая отправка формы или индикаторы отправки.

> **Примечание**: Перед началом работы рекомендуется изучить существующие методы аутентификации и хранения пользовательских данных в проекте (например, как реализован вход/выход, где хранятся токены) и повторить использованные подходы для интеграции с бэкендом. Также проверьте, есть ли уже готовые компоненты для отображения аватара или загрузки файлов, чтобы избежать дублирования усилий.
